# AutoBlog 프로젝트 안내

이 저장소는 티스토리("생생꿀정보통", 근로기준법/퇴직금/임금 등 실용 금융정보 니치)와 네이버 블로그의
발행 큐 + GitHub Actions 알림 시스템입니다. 전체 배경과 로드맵은 `README.md`를 참고하세요.

## 새 글을 써달라는 요청을 받으면

1. `content/tistory/ideas.md`에서 아직 사용하지 않은 주제를 우선 고려하거나, 사용자가 지정한 주제로 작성합니다.
2. `content/tistory/queue/YYYY-MM-DD-slug.md` (티스토리) 또는 `content/naver/drafts/YYYY-MM-DD-slug.md`
   (네이버) 형식으로 파일을 만듭니다. frontmatter 필드는 `README.md`의 "새 글 추가하기" 섹션을 그대로 따릅니다.
3. 품질 게이트(`scripts/lib/qualityGate.ts`)를 통과하려면:
   - 본문 분량 — **티스토리 1,500자 이상**(근로기준법/세무 등 YMYL 인접 주제라 얇은 콘텐츠는 구글/네이버
     품질 평가에 불리함), **네이버 800~1,000자 내외**(정보 밀도보다 가독성·친근함 중심의 짧은 글)
   - "본 글은 정보 제공 목적이며 법률·세무 자문이 아닙니다" 류 면책 문구 포함
   - category, tags 필수 입력
   - 기존 `published/` 폴더의 글과 slug/title 중복 금지
4. 문체: 실용적이고 친근한 존댓말, 과장된 클릭베이트 제목 지양, 계산 공식/절차는 번호 목록으로 명확히 정리.
   법률·세무 관련 수치는 확인 가능한 일반 원칙 위주로 작성하고, 특정 연도의 세율·금액처럼 자주 바뀌는
   구체적 수치는 확실하지 않으면 단정적으로 쓰지 않습니다.
5. 네이버 → 티스토리 링크는 아래 원칙을 지킵니다 (근거: 네이버 검색 로봇은 외부 이탈을 유도하는 글을
   저품질로 판단할 위험이 있음):
   - **매 글마다 넣지 않습니다.** 네이버 글 3~4개 중 1개 꼴로만 티스토리 링크를 포함합니다.
   - 링크를 넣는 글에서도 본문 흐름상 자연스러운 위치에 **텍스트 하이퍼링크 1개**만 사용합니다
     (자동 렌더링되는 URL 카드보다 텍스트 링크가 안전). "더 자세한 절차/서류는 여기에 정리해
     두었습니다" 류 문구로 자연스럽게 연결합니다.
   - 링크가 없는 나머지 글은 네이버 안에서 완결되는 요약·후기·체크리스트 형태로 작성합니다.
6. `**굵게(괄호 포함)**`처럼 볼드 구간 안에 괄호를 넣으면 `formatForTistory.ts`가 쓰는 marked 렌더러가
   볼드 처리에 실패하고 `**`가 그대로 노출되는 버그가 있습니다. 괄호는 볼드 밖으로 빼서 작성하세요
   (예: `**민사소송**(지급명령 등)`).
7. 본문 중 사진/썸네일이 들어가면 좋을 위치에는 `<!-- 이미지 제안: 여기에 설명 -->` 형태의 HTML 주석을
   남겨둡니다. 이미지 자체는 자동화 대상이 아니라 사용자가 직접 준비/삽입하는 수동 단계이므로,
   주석은 위치를 알려주는 힌트 역할만 합니다 (실제 발행 화면에는 보이지 않음).

## 포맷팅 규칙 (자동 적용, 참고용)

붙여넣기용 HTML을 만들 때 `scripts/lib/formatForTistory.ts`의 `addSpacing()`이 `<h2>/<h3>/<p>/<ul>/<ol>/
<blockquote>/<hr>`에 자동으로 여백(margin)과 줄간격(line-height)을 인라인 style로 주입합니다. 티스토리
스킨 CSS에 관계없이 문단 사이 간격이 항상 넉넉하게 유지되도록 하기 위함이며, 글을 쓸 때 마크다운 문법만
지키면 되고 별도로 신경 쓸 필요는 없습니다. 이 간격 규칙을 앞으로도 계속 지켜야 하므로, `formatForTistory.ts`를
고칠 일이 있어도 `SPACING_STYLES` 로직 자체는 유지하세요.

## 발행 케이던스

`config/cadence.json` 기준 티스토리 주 4회, 네이버 주 3회(화/목/토)입니다. 이보다 무리하게 늘리지 않습니다 —
볼륨보다 꾸준함과 품질이 우선입니다 (자세한 이유는 `README.md` 참고).

## 글 작성/전략 논의 시 사용자에게 데이터 요청하기

케이던스나 다음에 쓸 주제, 카테고리 우선순위 같은 전략적 판단을 할 때는 감으로 추측하지 말고,
사용자에게 최근 데이터를 요청해서 근거로 삼습니다. 특히 아래 항목은 있으면 분석에 큰 도움이 됩니다
(사용자가 먼저 안 주면 먼저 물어볼 것):

- **구글 서치 콘솔**: 최근 28일/3개월 실적 리포트(노출수·클릭수·CTR·평균 게재순위, 쿼리별/페이지별),
  신규 발행 글의 색인 여부, 색인 오류 유무
- **애드센스 리포트**: 일별/카테고리별 페이지뷰, 노출수, 클릭수, CTR, 페이지 RPM, 예상 수익
- **티스토리 자체 통계**: 유입경로별(구글/네이버/다음) 비중, 최근 인기글 순위(이번에 확인한 것처럼)
- **네이버 블로그 통계**: 조회수, 방문자수, 유입경로, 이웃 증가 추이, 가능하면 티스토리로의 클릭 여부

이 데이터는 프로젝트 문서(`roadmap.md` 등)에 그대로 저장하지 않습니다 — 시점마다 값이 바뀌는 스냅샷이라
"의사결정 로그"에는 데이터에서 도출한 **결론**만 남기고, 원본 수치는 사용자가 그때그때 제공하는 대화
맥락으로 취급합니다.

## 코딩 스타일 (scripts/ 디렉토리 수정 시)

- TypeScript, 2칸 들여쓰기, ESM (`.js` 확장자로 상대 임포트)
- 주석은 한국어로, 꼭 필요한 경우에만 작성
